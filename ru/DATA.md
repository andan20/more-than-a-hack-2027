## Как получить данные

Доступ к материалам матча ограничен. Их предоставляют участникам, которые зарегистрировались и приняли условия использования данных.

1. Зарегистрируйтесь: **[<More Than A Hack 2027>](https://landing.mobileworldcapital.com/more-than-a-hack-2027)**.
2. Прочитайте и подпишите условия в регистрационной форме.
3. Вы получите ссылку для скачивания.
4. Распакуйте материалы в `data/`, сохранив исходные имена:

```text
data/
├─ tactical/
│  ├─ BAR-ATH_tactical.mp4
│  ├─ BAR-ATH_tactical_atd.xml              метаданные трекинга
│  ├─ BAR-ATH_tactical_atd.txt              трекинг игроков и мяча
│  ├─ BAR-ATH_tactical_homography.csv
│  └─ BAR-ATH_tactical_smart_tagging.xml
└─ broadcast/
   ├─ BAR-ATH_broadcast.mp4
   ├─ BAR-ATH_broadcast_atd.xml
   ├─ BAR-ATH_broadcast_atd.txt
   └─ BAR-ATH_broadcast_homography.csv
```

Имена файлов нигде в репозитории не заданы жёстко: все их формирует `games.py`. Переменная `MTAH_DATA_DIR` позволяет перенести весь набор в другое место без дополнительных изменений:

```python
from games import asset_paths
asset_paths()["atd_raw"]                    # tactical, по умолчанию
asset_paths(source="broadcast")["video"]
```

Всё содержимое `data/` исключено из Git. Не добавляйте его в коммиты и не распространяйте: допустимые и недопустимые действия с ним определяются подписанными вами условиями.

**Для оценивания эти материалы не нужны.** Оценщик читает только CSV, поэтому работает сразу после клонирования репозитория, даже если данных у вас ещё нет.

## Автоматические данные трекинга (ATD)

**Что это.** Результат работы системы компьютерного зрения Metrica: положение и скорость каждого объекта, который она видит на поле, для каждого кадра видео, **включая мяч**. Данные получены автоматически из видео — они не исправлены и не проверены вручную.

Это экспорт Metrica в формате FIFA/EPTS: XML с метаданными и текстовый файл с исходными данными. `kloppy` читает эту пару напрямую:

```python
from kloppy import metrica
from games import asset_paths

paths = asset_paths()
dataset = metrica.load_tracking_epts(meta_data=paths["atd_meta"], raw_data=paths["atd_raw"])
```

`dataset.to_df()` даёт одну строку на кадр: `frame_id`, `ball_x`, `ball_y`, затем `1_x`, `1_y`, `1_s` для каждого слота трека — координаты и скорость в м/с. При 25 кадрах/с 25 строк соответствуют одной секунде.

**Координаты нормированы в диапазон 0–1**, а не выражены в метрах. Чтобы получить метры, умножьте их на размеры поля:

```python
dataset.metadata.pitch_dimensions.pitch_length   # 105
```

Метаданные указывают 105 × 68 м; в `games.py` используются 105,3 × 68,0 м, измеренные по исправленному трекингу. Разница в 30 см важна только при вычислении расстояний в метрах.

### Чего здесь нет

**Нет идентичностей игроков.** Для 22 игроков на поле предусмотрено **46 слотов треков**. Они называются `Track 1`…`Track 46`, а их `ShirtNumber` — индекс слота, **не номер на футболке и не идентификатор человека**. Слоты появляются, исчезают и меняют привязку к людям, когда трекер теряет и заново обнаруживает игроков. Вы получаете только координаты и принадлежность к команде, поэтому анализ должен быть коллективным, а не индивидуальным по игрокам.

Во время игры ожидайте около 22 отслеживаемых объектов: среднее по оцениваемым кадрам — 20,5. Иногда их больше 22, когда трекер дублирует кого-то.

### Мяч отсутствует на 43% всех кадров и на 41% оцениваемых

Это самый важный отдельный факт о наборе данных. Мяч присутствует на **56,9%** всех кадров (113 488 / 199 319) и на **59,3%** оцениваемых (94 214 / 158 857).

Мяч — самый информативный и одновременно самый ненадёжный сигнал: перекрытия, скопления игроков в штрафной и мячи в воздухе приводят к его потере. Поэтому он непропорционально часто отсутствует именно на важных кадрах. Подход, предполагающий наличие координат мяча в каждом кадре, столкнётся с этим уже на второй день — учитывайте проблему с первого. Отсутствующие наблюдения обозначаются `NaN` и для игроков, и для мяча.

`starter/02_tracking_atd.ipynb` показывает загрузку и визуализацию;
`starter/03_first_submission.ipynb` превращает ATD в решение, которое можно оценить.

## Smart Tagging

**Автоматическая** тактическая разметка Metrica для тактического видео: 638 игровых фаз и стандартных положений. Каждый эпизод — интервал с кодом и набором тегов. Формат — SportsCode XML.

```python
from kloppy import sportscode
from games import asset_paths
events = sportscode.load(asset_paths()["smart_tagging"]).to_df()
```

Вы получаете `timestamp`, `end_timestamp` (временные интервалы pandas), `code` и по одному столбцу для каждой группы тегов.
**Названия столбцов тегов начинаются с заглавной буквы**: столбец называется `Team`, а не `team`. Коды записаны в верхнем регистре (`SET PIECES`), а значения тегов — с заглавными начальными буквами (`Kick Off (Start)`). Поэтому сравнивайте без учёта регистра, если не хотите получать пустые результаты без предупреждений.

`starter/load_smart_tagging.py` делает то же самое средствами стандартной библиотеки, без kloppy.

| код | количество | | код | количество |
|---|---|---|---|---|
| `PLAYERS IN THE BOX` | 97 | | `CREATING CHANCES` | 30 |
| `BALL IN FINAL THIRD` | 93 | | `DEFENDING IN DEFENSIVE THIRD` | 30 |
| `BALL IN THE BOX` | 72 | | `LONG BALL` | 29 |
| `PROGRESSION` | 66 | | `ATTACKING TRANSITION` | 24 |
| `DEFENDING IN MIDDLE THIRD` | 66 | | `DEFENSIVE TRANSITION` | 24 |
| `SET PIECES` | 59 | | `BUILD UP` | 22 |
| | | | `DEFENDING IN ATTACKING THIRD` | 22 |
| | | | `GOALS` | 4 |

| группа тегов | значения |
|---|---|
| `Team` | `Barcelona` (314) · `Atletic Club` (288) · **`N/A` (36)** |
| `Half` | `1st Half` · `2nd Half` — строки, а не числа |
| `Type` | `Throw-in` (26) · `Corner Kick` (12) · `Goal Kick` (10) · `Free Kick` (5) · `Kick Off (After Goal)` (4) · `Kick Off (Start)` (2) |
| `Side` | `Central` · `Left` · `Right` |
| `Direction of ball entry` | `Horizontal` · `Vertical` · `Diagonal` |
| `Max Players in the box` | `1` … `6` и `7+` — **строка**, а не целое число |

### Отсчёт времени — проверено

`<start>` и `<end>` — это **секунды от первого кадра тактического видео**, поэтому `round(seconds * 25)` даёт номер видеокадра; никаких дополнительных поправок не требуется. Это проверено по начальным ударам обоих таймов; проверку можно повторить командой `python starter/load_smart_tagging.py`.

### Почему это полезно и чем это не является

У каждой фазы есть тег команды, и у каждого владения есть команда; каждое стандартное положение — возобновление игры, а каждое возобновление завершает отрезок, когда мяч был вне игры. Это бесплатно даёт сильную априорную информацию об обеих составляющих вашей метки. Однако:

- **Это результат автоматического вывода, а не эталонная разметка.** Metrica генерирует его автоматически из тех же видео и трекинга, которые есть у вас, без ручной проверки. Поэтому здесь есть ложноположительные и ложноотрицательные результаты, как у любого автоматического вывода. Рассматривайте тег как свидетельство, а не как готовый ответ.
- **`Team` не всегда указывает команду.** 36 эпизодов имеют значение `N/A`, включая **все вбрасывания** — как раз те возобновления, где знание команды было бы особенно полезно. Явно обработайте этот случай.
- **Интервалы — это фазы, а не владения.** Фаза Build Up может совпадать с одним владением, охватывать лишь его часть или захватывать два. Прямое копирование интервала в метки переносит все его ошибки в ваше решение.

## Гомография

**Что это.** Матрица 3×3 для каждого кадра видео, которая переводит позицию на поле в пиксель изображения. Она связывает трекинг с видео: можно спроецировать игроков на кадр, чтобы увидеть, что видела модель, или перевести пиксель обратно в позицию на поле.

CSV с одной строкой на кадр; `frame` отсчитывается от 0. Для тактической записи это тот же индекс, что и номер строки решения.

```text
frame,h00,h01,h02,h10,h11,h12,h20,h21,h22,reprojection_error,valid
11185,1822.663,-511.2005,44.48168,1.698323,169.2971,255.7303,-0.01907188,-0.5269586,1,0.2910854,1
```

Столбцы 1–9 содержат матрицу в построчном порядке, поэтому достаточно `row[1:10].reshape(3, 3)`.

**Она преобразует нормированные координаты поля (0–1) в пиксели изображения.** ATD использует тот же диапазон 0–1, поэтому координаты из трекинга можно передавать напрямую:

```python
from starter.load_homography import load, project
H, reprojection_error, valid = load()
x, y = project(H[frame], tracking_x, tracking_y)     # -> пиксели
```

**Проверяйте `valid` перед использованием матрицы.** Если он равен 0, девять столбцов матрицы содержат `NaN`, поскольку для этого кадра преобразования поля вообще нет. В тактическом файле все матрицы допустимы. В файле телетрансляции — только на 65,8% кадров; остальные — повторы, крупные планы и кадры трибун. Это 122 отрезка, самый длинный — более полутора минут.

`reprojection_error` показывает величину ошибки подогнанной матрицы, поэтому **чем меньше, тем лучше**. Верхней границы нет: в телетрансляции значение достигает 304. В тактическом файле медиана во время игры — 0,24, а в перерыве, когда камера не направлена на поле, — около 1,5.

Эти два столбца отвечают на разные вопросы: `valid` — существует ли вообще матрица, `reprojection_error` — насколько можно ей доверять.

## Телетрансляция

Телевизионная запись — то, что обычно смотрит аналитик. Для неё есть собственные ATD и гомография в тех же форматах, что описаны выше.

Она **не выровнена по кадрам с тактическим видео**, таблица соответствий не предоставляется. Здесь есть переключения камер, повторы и зум, собственное количество кадров, а для трети кадров нет пригодной гомографии. Если решите использовать эту запись, сопоставление с тактическими кадрами — ваша задача.

```python
asset_paths(source="broadcast")
```

## Открытая эталонная разметка

`evaluation/gt/BAR-ATH_possession_gt_public.csv` находится в этом репозитории, скачивать отдельно не нужно. Это полноразмерный файл из 199 319 строк, точно как файл решения, с реальными метками только для **первых 5 минут игры**: видеокадры **11185 … 18684**, `H` — 3454 · `A` — 2577 · `D` — 1469; 17 владений со средней длительностью 14,2 с. Всё за пределами этого окна обозначено `X` и не оценивается, поэтому решение для полного матча можно проверять на этом файле без изменений. `..._public_meta.json` содержит те же числа в машиночитаемом виде.

Эта разметка нужна, чтобы проверить корректность вашего процесса обработки, **а не для построения рейтинга** — см. [EVALUATION.md](EVALUATION.md). Итоговый рейтинг использует закрытую эталонную разметку полного матча — 158 857 оцениваемых кадров.
