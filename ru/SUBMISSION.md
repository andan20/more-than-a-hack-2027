# Сдача решения

## Файл владений

CSV с заголовком и одной строкой на каждый видеокадр.

```text
frame,label
0,X
1,X
...
11185,A
11186,A
...
199318,X
```

| требование | почему оно строгое |
|---|---|
| заголовок — ровно `frame,label` | регистр и пробелы по краям допускаются; всё остальное — нет |
| ровно **199 319** строк данных | по одной на кадр тактического видео |
| `frame` — `0 … 199318`, по порядку | **намеренно** дублирует порядок строк: превращает ошибку на единицу в явную ошибку проверки, вместо незаметного смещения оценки на один кадр повсюду |
| `label` — одна из `H` `A` `D` `X` | перед проверкой пробелы по краям удаляются, а буквы переводятся в верхний регистр, поэтому `h` и ` H ` допустимы |
| никаких пустых ячеек | пустое поле — ошибка и отклоняется. **Чтобы отказаться от ответа, пишите `X`** |

UTF-8, окончания строк `\n` или `\r\n`, без дополнительного столбца индекса. Подойдёт всё, что может разобрать `pandas.read_csv`.

Кадры, где **эталонная разметка** содержит `X`, никогда не оцениваются: перерыв, время до начального удара и после финального свистка. На оцениваемом кадре `X` считается ошибкой для `macroF1`. Для `spellF1`, определяющей рейтинг, оценщик перед сопоставлением владений заменяет её последней вашей меткой в этом тайме; цена равна цене повторения этой метки. См. [EVALUATION.md](EVALUATION.md).

### Проверьте файл перед отправкой

```bash
python evaluation/validate_submission.py my_submission.csv
```

Запускаются **ровно те же** проверки, что и в официальном оценщике. Файл, не прошедший их, при оценивании пропускается с краткой причиной и ничего не получает.

## Три материала для сдачи

### 1. Файл владений

Описан выше. Именно он оценивается и определяет место в рейтинге.

### 2. Публичный репозиторий кода

Всё необходимое для получения файла решения из предоставленных данных: исходный код, зависимости с зафиксированными версиями, инструкции по установке и запуску, а также команда, заново генерирующая файл.

Требование: человек с набором данных и вашим репозиторием должен суметь воспроизвести ваш файл. Не приблизительно — тот же самый файл.

Убедитесь, что данных матча в репозитории нет. Репозиторий публичный, а данные распространять нельзя.

### 3. Технический документ

Короткий: нескольких страниц достаточно. PDF или Markdown. Он должен описывать:

- **подход** — что вы построили и почему выбрали именно это;
- **какие материалы использовали и как** — рассказать, что вы попробовали и *отбросили*, не менее полезно;
- **реализованные правила владения** — как вы трактовали свободные мячи, единоборства и возобновления игры;
- **ограничения** — где решение ошибается и что вы исправили бы при наличии дополнительного времени;
- **воспроизведение** — как его запустить.

## Как отправить

Одна Google Form: три поля с материалами плюс название команды.

**Ссылка для отправки будет разослана по электронной почте всем зарегистрированным участникам.**

| поле | содержимое |
|---|---|
| Team Name | название, указанное всеми участниками команды в регистрационной форме |
| Possession file | загрузите свой `.csv` (около 1,9 МБ) |
| Public code repository URL | публичная ссылка |
| Short technical document | загрузите `.pdf` или `.md` |

**Срок сдачи: 17 ноября 2026 года.**

Четыре практических момента: форма менее снисходительна, чем папка.

- **Назовите CSV и технический документ по названию команды: `<team_name>.csv` и `<team_name>.pdf`.** Оценщик подписывает каждую строку рейтинга именем файла — так ваше название попадёт в таблицу.
- **Для загрузки нужен аккаунт Google.** Лучше узнать об этом сейчас, а не в последний момент.
- **Один ответ на команду.** Его можно редактировать; оценивается последняя версия, отправленная до срока сдачи.
- **Текущего рейтинга и обратной связи нет.** Открытое 5-минутное окно и `validate_submission.py` — единственные сигналы до дедлайна. Поэтому проверяйте именно тот файл, который собираетесь загрузить, а не ранее созданную версию.

## Правила

Полные правила — в **[RULES.md](RULES.md)**. Два из них определяют саму задачу, а не организацию соревнования:

- **Метки должны быть созданы алгоритмом.** Ручная разметка данных не является решением.
- **Нельзя использовать закрытую эталонную разметку** или любые производные от неё данные сверх опубликованных здесь 5 минут.
