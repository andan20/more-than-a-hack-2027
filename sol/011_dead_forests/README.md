# 011_dead_forests: D / LIVE, precision-first comparison

Run All from this directory or the repository root. All model and analysis logic is in this notebook. Approved libraries only: numpy, pandas, scikit-learn, PyTorch, tqdm, Jupyter and standard library.

Подготовка: нужны локальные признаки 008 и маски broadcast_alignment из эксперимента 009. Их подготовка описана в 009; исходные данные не публикуются. Выходы — local_review/experiments/011_dead_forests/. tqdm и progress.json показывают прогресс. Случайное зерно 42, CPU, четыре потока.

Два режима: weak — только слабые метки (подбор на втором тайме, затем переобучение на обоих); hybrid — 25% веса слабых меток и 75% публичных. Hybrid: подбор на четвёртой минуте, обучение на первых трёх с отступом 20 с. После выбора переобучение на первых четырёх с отступом 20 с перед последней минутой. Последняя минута не участвует в обучении/подборе, но ранее неоднократно исследовалась. Пять минут для hybrid смешивают обучение, подбор и диагностику: это НЕ held-out оценка.

Выбор по recall при precision>=0.95 на участке подбора и минимум 100 предсказанных кадров D. Дополнительно сохраняется порог для 0.99. Если условие недостижимо, D не предсказывается; precision не объявляется равным 1. Порог и фильтр не меняются по последней минуте. Перенос порога после переобучения не гарантирует precision. Слабая проверка измеряет согласие с эвристикой, не истинное качество.

Признаки причинные, прошлые окна до 10 с; офлайн-фильтр использует будущий контекст, заполняет разрывы до 10 кадров и удаляет D короче выбранной длительности. Предобработка обучается только на training. Перебор: 4 конфигурации × 2 режима × 18 порогов × 4 фильтра. Порог задаёт решение, не является гарантией калибровки вероятности.

Модель выводит D/LIVE/X, H/A не назначаются: конкурсные spellF1 и трёхклассовый macroF1 неприменимы. Данные и предсказания остаются локальными. Файлы *_model.pkl — только собственные доверенные артефакты. Веса MLP сохраняются как массивы, функция predict восстанавливает сеть. Ноутбук проверяет совпадение предсказаний после сохранения/загрузки.

Для подбора офлайн-фильтра учитываются по 10 с контекста вероятностей вокруг четвёртой минуты, включая входные признаки начала пятой минуты, но не её метки. Это трансдуктивная офлайн-диагностика, не строго изолированный потоковый тест.

Воспроизводимая подготовка слабых broadcast-меток опубликована в `sol/010_dead_logistic/prepare_broadcast_labels.ipynb`; сначала нужны локальные признаки из секции подготовки 008. Рабочая копия исходных данных должна оставаться локальной.
