# 001 — квадрат 5×5 м и голосование по 100 кадрам

Детерминированный baseline определения владения. Обучения и весов нет: модель задаётся ноутбуком `experiment.ipynb` и параметрами `config.json`.

## Определение команды

1. Перевести нормированные координаты ATD в метры, используя размеры поля из `games.py`.
2. В каждом кадре посчитать игроков обеих команд в квадрате со стороной 5 м, центрированном на наблюдаемом мяче. Границы включаются.
3. Команда с большим числом игроков получает один голос; равенство, отсутствие игроков или мяча дают нулевой голос.
4. Суммировать голоса последних 100 кадров, включая текущий. Положительная сумма означает `H`, отрицательная — `A`. Это временное окно из 100 кадров, а не 100 непустых голосов.
5. При равенстве сохранить последнюю выбранную команду. Если её ещё нет, выдать `X`. История и предыдущая команда сбрасываются на границе тайма и при `D`.

Окно использует только прошлое и текущий кадр. Его длина — 4 секунды, поэтому задержка на сменах владения ожидаема. Нет искусственного преимущества хозяев при равенстве. Нет подстановки ближайшего игрока, если квадрат пуст.

## Эвристика мяча вне игры

Близость к боковой линии **не** считается остановкой сама по себе. `D` появляется при одном из условий:

- координаты мяча больше чем на 0,5 м за границей поля в течение 3 последовательных кадров;
- медианная скорость игроков не выше 0,7 м/с в течение 25 кадров и скорость мяча не выше 0,35 м/с в течение 25 кадров;
- тот же низкий темп игроков и отсутствие мяча в течение 50 кадров.

В интервале автоматического события `SET PIECES` порог подтверждения неподвижного мяча сокращается до 15 кадров. Остальные условия сохраняются. Ни тег команды, ни интервал события не копируются в итоговый ответ.

После входа в `D` состояние сохраняется до наблюдения мяча внутри поля со скоростью от 0,8 м/с в течение 3 кадров либо медианной скорости игроков от 1,8 м/с в течение 12 кадров. При наблюдаемом мяче за заданной внешней границей выход из `D` не разрешается.

Скорости получаются из разности координат за 10 кадров (0,4 секунды). Для мяча требуется непрерывная наблюдаемость этого интервала. Для игроков используется медиана по минимум 10 доступным трекам, значения выше 12 м/с отбрасываются. Готовый канал скорости ATD не используется из-за неоднозначных единиц. Все пороги зафиксированы до чтения публичной эталонной разметки.

## Воспроизведение

Данные должны находиться в `data/` или в каталоге, заданном `MTAH_DATA_DIR`. Используются только tactical ATD и Smart Tagging. Видео и гомография не нужны.

Из корня репозитория установите зависимости в отдельное окружение:

```bash
python -m pip install -r sol/001_box5_vote100/requirements.txt
```

Откройте `experiment.ipynb` в Jupyter, выберите это окружение и выполните все ячейки. Также можно запустить из корня репозитория:

```bash
python -c "import nbformat; from nbclient import NotebookClient; NotebookClient(nbformat.read('sol/001_box5_vote100/experiment.ipynb', as_version=4), kernel_name='python3', timeout=600).execute()"
```

Ядро `python3` должно использовать окружение с указанными зависимостями. Проверенное окружение — Python 3.13.9. При запуске через API nbclient можно явно указать путь к интерпретатору в KernelManager.

Выходные материалы сохраняются **за пределами папки решения**:

```text
local_review/experiments/001_box5_vote100/
    box5_vote100.csv       # все 199319 кадров, frame,label
    validation.log        # проверка официальным валидатором
    metrics.json          # метрики только на публичных 5 минутах
    comparison.json       # сравнение с авторскими baseline
    diagnostics.json      # диагностика и версии окружения
```

Воспроизведение прогнозов не использует эталонные метки. Публичная разметка читается только после записи CSV и используется исключительно для оценки. Закрытая разметка не используется.

## Ограничения

- Преобладание игроков около мяча не гарантирует контролируемого владения.
- Треки могут дублироваться или менять идентичность, что влияет на подсчёт и движение.
- Четырёхсекундное голосование запаздывает; короткие владения могут исчезать.
- При длинном пропуске мяча предыдущая команда может сохраняться ошибочно.
- Остановки определяются эвристически: спокойная живая игра может стать `D`, а активная остановка — остаться живой игрой.
- Отсутствие наблюдений после остановки даёт `X`; оценщик spellF1 заполняет его предыдущей меткой, в том числе `D`.
- Smart Tagging — автоматические офлайн-фазы, а не точные моменты свистков.
- Открытых 5 минут недостаточно для надёжного выбора порогов или оценки полного матча.
