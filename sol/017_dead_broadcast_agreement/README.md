# 017 — Agreement with broadcast and conservative D cores

Последний бинарный опыт: кандидаты D только при согласии вероятностей 009/010/среднего/минимума с broadcast-правилом. Отдельно правило broadcast, старый D-детектор 008, а также объединение согласованных кадров со старым D-детектором. Никакие эталонные метки не становятся входными признаками. Плотная сетка 53 порога, четыре длительности и четыре отступа от границ.

Выбор на первых четырёх публичных минутах, последняя минута только для диагностики после фиксации выбора. Метки пятой минуты не используются при подборе, но офлайн-фильтр видит входные вероятности полного матча. Цели P>=.95/.99, максимум recall, минимум 100 кадров D на подборе. Последняя минута ранее исследовалась и не является независимым тестом.

Run All после 008–014 и broadcast_alignment. Общие функции берутся из 010, подготовка вероятностей из 014, обучение родителей не запускается. Предсказания и исходные данные остаются локальными. Публикуются только код и конфигурация. Используется сохранённая локальная маска 008; при её отсутствии нужно выполнить ноутбук 008. Это общий алгоритм, без ручных временных исключений. H/A не назначаются.

Воспроизводимая подготовка слабых broadcast-меток опубликована в `sol/010_dead_logistic/prepare_broadcast_labels.ipynb`; сначала нужны локальные признаки из секции подготовки 008. Рабочая копия исходных данных должна оставаться локальной.
